## ansible-pullとGitHubでコンテナの構成管理

ProxmoxのLXCの構成管理でとても悩んでいました。
今までは手動でセットアップしてテンプレート化、そのテンプレートをクローンするということをしていました。
しかし、この方法だと後から全LXCの設定変更などをしたい場合に、個別でSSH接続して同じ作業を繰り返す必要がありました。
そこで**ansible-pull** + **GitHub**で構成管理することを決めました。

構成管理の内容の例は下記の通りです。

- 非rootユーザーの作成
- apt packageのインストール
- Dockerのインストール etc...

## ansible-pullの基本的な設定

```yml
# local.yml
---
- name: Setup LXC Container Environment
  hosts: localhost
  become: true
  gather_facts: true

  roles:
    - common
    - users
    - docker
```

```yml
# inventory/hosts.yml
all:
  hosts:
    localhost:
      ansible_connection: local
```

```ini
# ansible.cfg
[defaults]
timeout = 30
callbacks_enabled = profile_tasks
gathering = smart
fact_caching = jsonfile
fact_caching_connection = /tmp/ansible_facts
```


## ansible-pullがフリーズする

まずはansible-pullがちゃんと動作することを確認するために、2つの軽めのタスクを実行してみました。

```yml
# apt packageのインストール
---
- name: Install apt packages
  ansible.builtin.apt:
    name:
      - curl
      - python3-passlib
      - language-pack-ja-base
      - language-pack-ja
    state: present
    update_cache: true
    cache_valid_time: 43200
```

```yml
# 非rootユーザー「ubuntu」の作成
---
- name: Ensure ubuntu user exists
  ansible.builtin.user:
    name: ubuntu
    password: "{{ 'ubuntu' | password_hash('sha512') }}"
    shell: /bin/bash
    uid: 1000
    groups: 
      - sudo
    append: true
    create_home: true
    state: present
    update_password: on_create
```

## なぜこんなにもフリーズするのか

考えられる原因は2つあります。

### タスクごとにSSH接続している

```txt
【タスクごとにSSH接続を張り直す】

タスク1   ─────────────────────────────────
          ↓ SSH握手（数百ms〜1秒）
          ┌───────────────────┐
          │     実行          │
          └───────────────────┘
          ↓ SSH切断

タスク2   ─────────────────────────────────
          ↓ SSH握手（また数百ms〜1秒）
          ┌───────────────────┐
          │     実行          │
          └───────────────────┘
          ↓ SSH切断

タスク3   ─────────────────────────────────
          ↓ SSH握手（また数百ms〜1秒）
              ...

          30タスク × SSH握手 = 最大30秒以上が"接続"だけで消える
```

タスクごとSSH接続して切断しているので、処理コストがタスクの分だけ増加。
ただし、今回はlocalhost(自分自身)に対して実行しており、リポジトリからの取得でしかSSHを使ってないので対象外。

### タスクごとにPythonが起動している

```txt
【タスクごとにPythonを起動・終了する】

タスク1   ┌─ python3 起動 ─┐  ← 300〜800ms
          │ モジュール実行  │
          └─ プロセス終了 ─┘

タスク2   ┌─ python3 起動 ─┐  ← また300〜800ms
          │ モジュール実行  │
          └─ プロセス終了 ─┘

タスク3   ┌─ python3 起動 ─┐  ← また300〜800ms
          │ モジュール実行  │
          └─ プロセス終了 ─┘

          30タスク × 300〜800ms = 最大24秒が"起動"だけで消える
          LXCのoverlayFSでファイルI/Oが遅いとさらに悪化する
```

タスクごとPythonのプロセスを起動して終了しているので、処理コストがタスクの分だけ増加。

## Mitogenで爆速化へ

Mitogenは、Ansibleの通信モデルを根本から置き換えるライブラリです。

https://mitogen.networkgenomics.com/ansible_detailed.html

改善のポイントは3つ。

- **SSH接続が最初の1回だけ** — 以降はUnixパイプ経由で通信
- **Pythonプロセスを常駐・再利用** — 起動コスト300〜800ms/タスクがゼロになる
- **モジュールコードをRAMにキャッシュ** — ファイルシステムへのZIP展開・削除がほぼなくなる

## Mitogen導入手順

### 1. Mitogenの取得

URLは[公式サイト](https://mitogen.networkgenomics.com/ansible_detailed.html#installation)の`Installation`セクションの2番にあるリンクをコピーしてください。

![Mitogen公式サイトのInstallationセクション](/images/4846c4e26dda25/mitogen-installation-section.webp)

```bash
curl -L -o /tmp/mitogen.tar.gz https://files.pythonhosted.org/packages/source/m/mitogen/mitogen-0.3.47.tar.gz
```

### 2. ダウンロードした圧縮ファイルを解凍

```bash
tar zxvf /tmp/mitogen.tar.gz -C /opt/
```

### 3. ansible.cfgに設定を追記

```ini
[defaults]
strategy_plugins = /opt/mitogen-0.3.47/ansible_mitogen/plugins/strategy
strategy = mitogen_linear
```

## 体感速度の変化

公式ドキュメントでは**1.25〜7倍の高速化**とされており、ユーザー報告では「45分 → 3分」という事例もあるそうです。

| 処理 | Default | Mitogen |
|---|---|---|
| SSH接続回数 | タスク数 × N回 | **最初の1回のみ** |
| Python起動コスト | 毎タスク300〜800ms | **ゼロ（常駐）** |
| ファイルI/O | 毎タスクZIP展開 | **RAMキャッシュ** |
| ネットワーク通信量 | 多 | **約1/5** |

Mitogen導入後は、フリーズすることがなくなって完走するようになりました。

## まとめ

`ansible_connection: local`でSSHを使っていなくてもフリーズしていたのは、Python起動コストとoverlayFSのI/O遅延が積み重なっていたからだったと思われます。
Mitogenを入れた後はフリーズが消えて完走するようになり爆速化しました。
`ansible-pull`を使っているなら、Mitogenをぜひお試しください。
