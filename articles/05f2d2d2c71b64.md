## プロローグ: コンピューターは「0.1+0.2」ができないの？

「ねえ、**0.1 + 0.2** っていくつ？」
「**0.3**でしょ！ 簡単すぎ！」

そうですよね。でも、コンピューターに同じ質問をしてみると...

```python
>>> 0.1 + 0.2
0.30000000000000004
```

**0.3**じゃない！ **0.300000...4** って何！？

これはコンピューターが計算ミスをしたわけではなく、コンピューターの「数字の数え方」に隠されたヒミツがあります。

私の友人が「小数同士を足した結果が、ある数と同じかどうか」を比べるプログラムを作っていたとき、**どう見ても同じはずなのに「ちがう！（false）」と判定されてしまい、何時間も原因探しに悩んでしまいました。**

この記事では、コンピューターが小数を計算する仕組みを「おもり」に例えて図解で分かりやすく解説します。

:::message
難しい専門的な内容については、ここでは説明しません。
:::

## 第1章: 数字の「重み」のヒミツ

私たちが普段使っている数字と、コンピューターの数字。何が違うのでしょうか？
まずは、言葉の意味から見ていきましょう。

- **10進数 (じゅうしんすう)**: 私たちが使う数え方。0〜9の10種類の数字を使い、**10たまると次のケタに進みます。**
- **2進数 (にしんすう)**: コンピューターの数え方。0と1の2種類しか使いません。**2たまると次のケタに進みます。**

### ケタは「おもり置き場」

数字の「ケタ」は、それぞれ**決まった重さのおもりを置く場所**だと考えてください。

### 10進数は「10倍」ずつ増える

10進数のケタ（おもり置き場）は、左に1つ進むごとに重みが**10倍**になります。
基準（きじゅん）になるのは **「1」** です。

- **1の位**：重さ 1 のおもりを置く場所
- **10の位**：重さ 10 のおもりを置く場所
- **100の位**：重さ 100 のおもりを置く場所

たとえば、**「291」** という数字は、こんな指示書になります。

- 「100」のおもりを **2つ** 置く
- 「10」のおもりを **9つ** 置く
- 「1」のおもりを **1つ** 置く

![10進数の整数の重み](/images/05f2d2d2c71b64/image2.webp)

:::message
10進数は0〜9まで使うので、おもりは「置かない(0個) か、1〜9個置く」になります。
:::

### 2進数は「2倍」ずつ増える

コンピューターの「2進数」は、左に1ケタ進むごとに重みが**2倍**になります。
ここでも基準は **「1」** です。

- **1の位**：重さ 1 のおもりを置く場所
- **2の位**：重さ 2 のおもりを置く場所
- **4の位**：重さ 4 のおもりを置く場所
- **8の位**：重さ 8 のおもりを置く場所

たとえば、私たちの **「5」** という数字を2進数で表したいときは、こんな指示書になります。

- 「8」のおもりは **置かない**
- 「4」のおもりを **1つ** 置く
- 「2」のおもりは **置かない**
- 「1」のおもりを **1つ** 置く

（4 + 0 + 1 = 5！）

![2進数の整数の重み](/images/05f2d2d2c71b64/image3.webp)

おもりの場所を並べると、5は2進数で **「101」** と書くんです。

:::message
2進数は0と1しか使わないので、おもりは「1個置くか、置かないか」のどちらかになります。
:::

## 第2章: 小数は「半分」の世界

整数（せいすう）がわかったら、次は **小数（1より小さい数）** です。
今度は「1」を基準に、右側を見てみましょう。

### 10進数は「10で割る」

右に1ケタ進むごとに、重みは **10分の1（10で割った数）** になります。

- **1の位（基準）**
- **0.1の位**：重さ 0.1 のおもりを置く場所
- **0.01の位**：重さ 0.01 のおもりを置く場所
- **0.001の位**：重さ 0.001 のおもりを置く場所

たとえば、**「0.21」** という数字は、こんな指示書になります。

- 「0.1」のおもりを **2つ** 置く
- 「0.01」のおもりを **1つ** 置く
- 「0.001」のおもりを **置かない**

![10進数の小数の重み](/images/05f2d2d2c71b64/image4.webp)

### 2進数は「2で割る（半分にする）」

2進数も同じです。右に1ケタ進むごとに、重みは **2分の1（半分こ）** になっていきます。

- **1の位（基準）**
- **0.5の位**：重さ 0.5 のおもりを置く場所
- **0.25の位**：重さ 0.25 のおもりを置く場所
- **0.125の位**：重さ 0.125 のおもりを置く場所

![2進数の小数の重み](/images/05f2d2d2c71b64/image5.webp)

たとえば、私たちの **「0.625」** を2進数で表したいときは、こんな指示書になります。

- 「0.5」のおもりを **1つ** 置く
- 「0.25」のおもりは **置かない**
- 「0.125」のおもりを **1つ** 置く

（0.5 + 0.125 = 0.625！）

おもりの場所を並べると、0.625は2進数で **「0.101」** と書きます。
組み合わせがピッタリ決まると、気持ちいいですね！

## 第3章: ナゾ解き！なぜ「0.1」や「0.2」が作れないの？

さて、本題です。
コンピューターに「0.1 や 0.2 を作って！」とお願いしてみましょう。
コンピューターは手持ちの「2進数のおもり」を組み合わせて、数字を作ろうとします。

### 「0.1」を作ってみる

| 順番 | おもりの重さ | 結果 |
| :--- | :--- | :--- |
| 1 | 0.5 | 大きすぎる（使えない） |
| 2 | 0.25 | 大きすぎる（使えない） |
| 3 | 0.125 | 大きすぎる（使えない） |
| 4 | 0.0625 | 使える！残りは 0.0375 |
| 5 | 0.03125 | 使える！残りは 0.00625 |
| 6 | 0.015625 | 大きすぎる（使えない） |
| 7 | 0.0078125 | 大きすぎる（使えない） |
| 8 | 0.00390625 | 使える！残りは 0.00234375... |

（...こうして、もっともっと小さいおもりを永遠に探し続けます！）

### 「0.2」を作ってみる

| 順番 | おもりの重さ | 結果 |
| :--- | :--- | :--- |
| 1 | 0.5 | 大きすぎる（使えない） |
| 2 | 0.25 | 大きすぎる（使えない） |
| 3 | 0.125 | 使える！残りは 0.075 |
| 4 | 0.0625 | 使える！残りは 0.0125 |
| 5 | 0.03125 | 大きすぎる（使えない） |
| 6 | 0.015625 | 大きすぎる（使えない） |
| 7 | 0.0078125 | 使える！残りは 0.0046875 |
| 8 | 0.00390625 | 使える！残りは 0.00078125... |

（...こちらも、ピッタリになるまで永遠に終わりません！）

こうして一生懸命組み合わせていくのですが、ここで大問題が発生します。

![0.1や0.2を作ろうとして苦戦するロボット](/images/05f2d2d2c71b64/image6.webp)

実は、2進数のおもり（0.5, 0.25, 0.125...）をどう組み合わせても、**絶対にピッタリ「0.1」や「0.2」にはならない**のです！
計算すると、永遠に終わりなく続いてしまいます。

私たちの世界で「1 ÷ 3」が「0.33333...」と永遠に終わらないのと同じことが、コンピューターの中では「0.1」や「0.2」で起きているんですね。

## 第4章: コンピューターの「おもり」には数に限りがある

コンピューターが持っている「おもりを置く場所（ビット）」の数は決まっています。
どんなにすごいコンピューターでも、だいたい53個くらいまでしかおもりを置けません。

これは[**「IEEE 754」**](https://ja.wikipedia.org/wiki/IEEE_754)という、世界中で決まっているコンピューターの計算のルールがあるからなんです。

![おもり置き場の限界](/images/05f2d2d2c71b64/image7.webp)

ピッタリにならないときは、一番近いところで **「ええい、もうここで終わり！」** と打ち切るしかありません。

ここで、ほんの少しだけ**ズレ**が生まれます。
たとえば、おもり置き場がいっぱいになったときに、まだ「0.000...1」だけ重さが足りなかったとします。

- ぴったりにならないから、少し足りないままにする？（切り捨て）
- それとも、最後のおもりを少し重いものに変えて、おまけで少し多めにする？（切り上げ）

コンピューターは、**「本当の数字に一番近い方」** を選んで、無理やりキリの良いところで終わらせます。算数の「四捨五入（ししゃごにゅう）」みたいなものですね。

その結果：

- コンピューターの「0.1」は、本当は **0.1よりほんのすこーーしだけ大きい数字**
- コンピューターの「0.2」も、本当は **0.2よりほんのすこーーしだけ大きい数字**

になっているのです。

:::message
数字の種類によっては、少し小さくなることもあります！
:::

## 第5章: ズレが重なって「0.300...4」になる

「ほんのすこしのズレ」なら気にならない気がしますよね。
でも、足し算をするとそのズレが目に見えるようになります。

```txt
  0.1（の代わりの、ちょっとだけ大きい数）
+ 0.2（の代わりの、ちょっとだけ大きい数）
------------------------------------------
  0.30000000000000004
```

ズレとズレが合体して、ついに無視できない大きさ（0.000...4）になって現れた。
これが **「0.1 + 0.2 ≠ 0.3」の正体** です！

![誤差が重なるイラスト](/images/05f2d2d2c71b64/image8.webp)

## 第6章: じゃあ、プログラミングではどう計算するの？

仕組みはわかりましたが、実際のアプリやゲームでお金を計算するときなどに、ちがう答えが出ては困りますよね。
「0.1 + 0.2」のズレにまどわされず、正しく計算するためにエンジニアが使っている「3つの方法」を紹介します。

### 1. 金額やポイントは「最小単位の整数」で持つ

一番確実なのは、**「最初から小数を計算に使わない」** という方法です。
たとえば、123.45円という値をあつかうとき、プログラムの中では「123.45」という小数ではなく、「12345（100分の1円が12345個）」という**整数**として保存・計算します。

- 1.5メートル → 150センチメートルとして持つ
- 10.5ポイント → 105（0.1ポイント単位）として持つ

計算の途中で「10倍」するのではなく、**データを持つ時点から整数にしておく**のが、バグを防ぐコツです。

### 2. 「ほぼ同じ」ならOKとする

「ピッタリ同じか」を比べるのではなく、「計算の結果が、ある程度のズレにおさまっているか」を確かめる方法です。

Pythonでは、`math.isclose()` という命令が用意されています。JavaScriptでは、下のような「ズレを許してくれる関数（nearlyEqual）」を作って使うのが一般的です。

```python
# Pythonでの例：math.isclose() を使って「ほぼ同じ」か比べる
import math

a = 0.1 + 0.2
b = 0.3

if math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-12):
  print("ほぼ同じ数だよ！")
```

```javascript
function nearlyEqual(a, b, relTol = 1e-9, absTol = 1e-12) {
  return Math.abs(a - b) <= Math.max(
    absTol,
    relTol * Math.max(Math.abs(a), Math.abs(b))
  );
}

const a = 0.1 + 0.2;
const b = 0.3;

if (nearlyEqual(a, b)) {
  console.log("ほぼ同じ数だよ！");
}
```

### 3. お金や税金の計算は「専用のツール」を使う

銀行のシステムやお店のレジなど、1円のズレも許されない厳密（げんみつ）な計算では、**「Decimal（デシマル）」** という特別なツールを使います。これは、コンピューターが10進数のまま計算してくれる仕組みです。

Pythonなら標準の `decimal` モジュール、JavaScriptなら `decimal.js` というライブラリがよく使われます。

```python
# Pythonでの例
from decimal import Decimal

# Decimalを使えば、10進数のまま正確に計算できます
print(Decimal('0.1') + Decimal('0.2')) # 0.3
```

```javascript
// JavaScript (decimal.js) での例
const Decimal = require('decimal.js');

// お金や税率の計算にはこれが一番向いています
const a = new Decimal('0.1');
const b = new Decimal('0.2');
console.log(a.plus(b).toString()); // "0.3"
```

## まとめ

1. **数字の重み**：10進数は10倍/10分の1ずつ、2進数は2倍/半分ずつ変わる。
2. **0.1のナゾ**：2進数のおもりをどう組み合わせても、0.1はピッタリ作れない。
3. **限界**：コンピューターが持てるおもりの数には限りがあるから、途中で打ち切る。
4. **誤差**：打ち切ったときの「小さなズレ」が重なって、0.300...4になる。

コンピューターは算数ができないのではなく、**「0と1（2進数）」という限られたルールの中で、精一杯ピッタリに近づこうとがんばっている**のです。
